# Inkling — 기획서 (v1)

> _A page that writes back — and lets go._
> 당신의 말을 받아 적고, 조용히 놓아주는 페이지.

작성일: 2026-08-07 · 상태: **검토 대기** · 저장소: `riddle-diary-web`

---

## 0. 한 문단 요약

사용자가 손글씨 또는 타이핑으로 종이 위에 하루를 적으면, AI가 **사람이 쓰는 속도로 손글씨를 써 내려가며** 응답한다.
양쪽의 글씨는 모두 일정 시간이 지나면 **잉크가 종이에 스며들듯 서서히 사라진다.**
남는 것은 기록이 아니라 _말해봤다는 경험_ 이다.

핵심 가설: **"지워진다"는 보장이 자기 개방(self-disclosure)의 문턱을 낮춘다.**

## 1. 연구 프레이밍

| 개념 | 이 프로젝트에서의 구현 |
|---|---|
| **Slow Technology** (Hallnäs & Redström, 2001) | 즉시 출력 금지. 응답은 실제 필기 속도(분당 60–90자)로만 나타난다. 기다림 자체가 인터페이스. |
| **Critical Design** (Dunne & Raby) | "AI는 모든 것을 기억하고 저장한다"는 지배적 전제를 뒤집는 반(反)제안. 소멸을 버그가 아닌 기능으로 제시. |
| **Ephemeral / Disappearing UI** | 화면에서 사라진 텍스트는 DOM에서도 제거된다. 스크롤백 없음, 저장 버튼 없음, 서버 로그 없음. |
| **Expressive Writing** (Pennebaker) | 감정 사건을 글로 옮기는 행위 자체의 임상적 효과. 손글씨 모드는 이 효과를 신체적으로 강화. |
| **Materiality of the interface** | 필압·속도·떨림이 남는 손글씨 vs. 균질한 타이핑. 두 모드를 토글로 비교 가능하게 하여 그 자체를 관찰 변인으로 삼음. |

> 헬스케어 맥락: 임상 도구가 아니라 **하루 회고(daily debrief) 인터랙션 프로브**. 진단·치료를 표방하지 않으며, 앱 내에 명시적 고지와 위기 자원 안내를 둔다.

### 이름
- 제품명(기본안): **Inkling** — "어렴풋한 생각" + "ink". 한글 병기 없이 사용.
- 대안: `Palimpsest`, `Marginalia`, `여백`. → 최종 확정 전 사용자 확인 1회.

## 2. 확정된 제품 결정 (사용자 승인 완료)

1. **손글씨 인식** — 캔버스 획을 PNG로 래스터라이즈해 `gpt-5.4-mini`의 **이미지 입력**으로 전송. 외부 OCR 없음. 화면에는 판독 텍스트를 표시하지 않는다(사용자가 쓴 진짜 글씨만 남음). 단, 다음 턴의 대화 문맥 유지를 위해 모델이 반환한 짧은 판독문을 **내부 히스토리에만** 보관한다.
2. **AI 기억** — 화면에서만 사라지고, **세션 동안 AI는 전부 기억한다.** (단, 세션 = 브라우저 탭. 새로고침/종료 시 메모리에서 소멸, 서버 영속 저장 없음.)
3. **페르소나** — 경청 위주 + 분명한 인격이 느껴지는 존재. 하루를 되짚고 털어놓는 상대. (§6 참조)
4. **v1 범위** — 텍스트 필기 애니메이션 + 마크 프리미티브(밑줄/동그라미/형광펜). 도표는 인터페이스만 열어두고 v2.

## 3. 정보 구조

```
/                단일 페이지 = "책상 위의 노트"
  ├ 상단 좌     워드마크 (Inkling)
  ├ 상단 우     모드(손글씨/타이핑) · 테마(라이트/다크/시스템) · 언어(KOR/ENG) · 설정
  ├ 본문        종이 표면. 두 목소리가 한 페이지를 공유. 말풍선 없음.
  └ 하단        입력 어피던스 (모드별로 다름)
/about           연구 노트: slow technology / critical design / 참고문헌 / 데이터 정책
/lab             (dev 전용) 잉크 엔진 데모 — 획 프리미티브 테스트베드
```

**대화 UI를 쓰지 않는다.** 말풍선·아바타·타임스탬프·전송 버튼 없음. 두 목소리는 **잉크의 종류**로만 구분된다.

- 사용자 잉크: 짙은 흑청색(라이트) / 따뜻한 오프화이트(다크). 안정적, 곧음.
- AI 잉크: 세피아·짙은 청록(라이트) / 은은하게 발광하는 강조색(다크). 미세하게 기울고 흘림체.

### 화면 상태
| 상태 | 내용 |
|---|---|
| 빈 화면 | AI 손글씨로 한 줄이 천천히 쓰였다가 사라짐. `오늘 어땠어요?` / `How was today?` |
| 사용자 입력 중 | 커서가 종이 위에서 깜빡임. 글자는 즉시 나타남(내가 쓰는 건 내 속도). |
| 전송 후 | 사용자 글이 확정(잉크가 마름) → 잠깐의 정적 → AI 잉크가 첫 획을 시작 |
| AI 작성 중 | 펜촉(nib) 광점이 글자를 따라 이동. 하단에 진행 표시 없음. |
| 소멸 | 쓰인 순서대로 글자 단위 stagger 페이드 → DOM 제거 |
| 오류 | AI 손글씨로 짧게: `지금은 잉크가 나오지 않아요.` |

- 본문 컬럼 `max-width: 34rem`, `line-height: 1.9` (필기체는 행간이 넉넉해야 읽힌다).

### 4.3 모션 원칙
- 스프링·바운스 **금지**. 모든 이징은 `cubic-bezier(.22,.61,.36,1)` 계열의 느린 유기 곡선.
- 최소 지속시간 하한을 둔다: UI 전환 ≥ 240ms, 잉크 관련 ≥ 900ms.
- 60fps 유지: 애니메이션 속성은 `opacity`, `transform`, `clip-path`, `stroke-dashoffset`로 제한.

## 5. 잉크 엔진 (핵심 기술 설계)

### 5.1 왜 "SVG냐 아니냐"가 답이 둘인가

| 대상 | 최선의 기법 | 이유 |
|---|---|---|
| **글자** (한/영) | HTML 텍스트 + **자소 단위 clip-path 리빌** | 한글 글리프의 스트로크 데이터를 얻을 방법이 없다. 폰트 아웃라인을 `stroke-dashoffset`으로 그리면 **윤곽선을 따라 그리는** 부자연스러운 결과가 나온다. 실제 폰트를 쓰고 **드러내는 방식**으로 필기감을 만드는 편이 한/영 모두에서 압도적으로 낫다. |
| **마크** (밑줄·동그라미·형광펜·화살표·도표) | **SVG path + `stroke-dashoffset`** | 진짜 경로가 존재하므로 펜 끝이 실제로 이동한다. 이게 "그려지는" 연출의 정석. |

→ **두 백엔드, 하나의 타임라인.** `InkClock`이 둘을 같은 시계 위에서 스케줄한다. 나중에 단일선(single-stroke) 폰트를 확보하면 라틴 텍스트만 `stroke` 백엔드로 승격 가능하도록 인터페이스를 열어둔다.

### 5.2 데이터 모델

```ts
type InkVoice = 'user' | 'ai'

type InkMark =
  | { kind: 'text';      text: string; voice: InkVoice }
  | { kind: 'underline'; targetId: string; wobble: number }
  | { kind: 'circle';    targetId: string; wobble: number }
  | { kind: 'highlight'; targetId: string }
  | { kind: 'freehand';  strokes: Point[][] }      // 사용자 손글씨
  | { kind: 'path';      d: string }               // v2 도표

type InkNode = {
  id: string
  mark: InkMark
  bornAt: number        // performance.now()
  writeMs: number       // 쓰는 데 걸리는 시간
  dwellMs: number       // 다 쓰고 머무는 시간
  fadeMs: number        // 사라지는 데 걸리는 시간
  pinned: boolean       // 사용자가 붙잡아 둔 상태
}
```

세션 스토어(zustand)는 `InkNode[]`와 `Message[]`(모델 히스토리)를 **분리** 보관한다. 전자는 사라지고, 후자는 세션 동안 남는다.

### 5.3 텍스트 필기 리빌 — 진짜처럼 보이게 하는 장치들

1. **자소 분할**: `Intl.Segmenter(locale, {granularity:'grapheme'})` — 한글 조합·이모지·결합문자 안전.
2. **가변 타이밍**: 글자당 기본 dur을 복잡도로 보정.
   `dur = base × (한글 1.5 | 라틴 1.0 | 숫자 0.9) × (1 + jitter±0.18)`
3. **펜 리프트**: 공백 뒤 +60ms, 쉼표 +140ms, 마침표/물음표 +320ms, 줄바꿈 +420ms. → 문장이 "생각하면서" 쓰인다.
4. **리빌 방식**: 글자마다 `clip-path: inset(0 100% 0 -.15em)` → `inset(0 -.05em 0 -.15em)`. 좌→우로 획이 자라는 느낌. (좌우 여유값으로 필기체 오버행 잘림 방지)
5. **펜촉(nib)**: 현재 글자의 rect를 따라가는 4px 광점 + 아주 미세한 종이 눌림 그림자.
6. **잉크가 마르는 과정**: 글자가 쓰인 직후 1.2s 동안 `color`가 진한 톤 → 기본 톤으로, `filter: saturate(1.25) → 1`. 젖은 잉크가 마르는 뉘앙스.
7. **베이스라인 미세 흔들림**: 글자별 `translateY(±0.4px) rotate(±0.35deg)` — 시드 해시로 결정론적 생성(리렌더 시 흔들리지 않게).
8. **속도**: 기본 분당 약 72자. 설정에서 `느리게 / 기본 / 조금 빠르게` 3단. 그 이상은 제공하지 않는다 (slow technology 원칙).

### 5.4 마크 프리미티브 — 손으로 그은 티 내기

`humanize(points, wobble)` 유틸: 목표 경로를 샘플링 → 각 점에 저주파 노이즈 → Catmull-Rom → 베지어 변환.

- **밑줄**: 대상 텍스트 rect 하단을 따라 1.5회 왕복하지 않고 한 번에, 끝을 살짝 위로 튀기며(플릭) 마무리.
- **동그라미**: 타원을 **약 1.08바퀴** 그려 시작점을 지나쳐 끝냄 — 사람이 그린 동그라미의 결정적 특징.
- **형광펜**: `stroke-width` = 행높이의 0.8배, `linecap: butt`, `mix-blend-mode: multiply`(라이트) / `screen`(다크), 시작·끝에서 폭이 살짝 줄어드는 tapered stroke.
- 모든 마크는 대상 텍스트가 **다 쓰인 뒤** 그어진다(사람 순서대로).

### 5.5 소멸 엔진

- 각 `InkNode`는 `animation-delay: dwellMs` 를 가진 CSS 키프레임으로 페이드. **메인 스레드 밖에서 도는 게 핵심** (JS rAF 루프 아님).
- 글자 단위 stagger: 쓰인 순서대로 사라진다. `--i` 커스텀 프로퍼티로 per-char delay.
- 페이드 곡선: `opacity 1 → 0.55` 구간은 느리게(잉크가 옅어짐), `0.55 → 0`은 상대적으로 빠르게. 동시에 `filter: blur(0 → 0.4px)`로 종이에 번지는 느낌.
- 완료 후 `setTimeout`으로 DOM 제거 → 노드 수 상한 유지.
- **붙잡기(hold)**: 텍스트를 길게 누르거나 `Space`를 누르고 있으면 그 순간 페이드 정지 + 잉크가 살짝 진해짐. 손을 떼면 다시 진행. → 접근성이자 인터랙션의 감정적 정점.

### 5.6 손글씨 입력

- `pointerdown/move/up` + `getCoalescedEvents()` + `pressure`/`tiltX` 수집.
- `perfect-freehand`로 아웃라인 폴리곤 → `<path fill>`. (stroke가 아닌 fill이라 필압 표현이 됨)
- 실행취소(⌘Z), 지우개, 전체 지우기. 획 수 상한 800.
- 전송: 오프스크린 캔버스에 종이색 배경 + 잉크 렌더 → `1024px` 폭으로 다운스케일 → `image/png` dataURL (상한 1.5MB, 초과 시 품질/해상도 자동 하향).
- 전송 트리거: 명시적 버튼(작게, 종이 우하단의 잉크 방울 아이콘) + `⌘Enter`. **자동 전송(무입력 타이머)은 하지 않는다** — 생각하며 멈추는 시간을 뺏으면 안 됨.

### 5.7 상호작용 세부 규칙 (1차 검토에서 보강)

이 규칙들이 없으면 "사라짐"이 감성이 아니라 **스트레스**가 된다.

1. **쓰는 동안에는 사라지지 않는다.** 사용자가 입력 중(타이핑 또는 펜 다운)이면 모든 노드의 dwell 타이머가 정지한다. 마지막 입력 후 2.5초가 지나야 다시 흐른다. → 페이지가 나를 기다려준다는 감각.
2. **탭이 숨겨지면 시간도 멈춘다.** `document.visibilityState === 'hidden'`이면 전역 클럭 정지. 돌아왔을 때 백지를 마주하는 일은 없다.
3. **AI가 쓰는 동안에는 그 턴의 사용자 글이 사라지지 않는다.** 응답이 끝난 시점부터 dwell 시작. 문맥 없는 답만 남는 상황 방지.
4. **전송 규칙(두 모드 공통)**: `Enter` = 줄바꿈, `⌘/Ctrl + Enter` 또는 종이 우하단 **잉크 방울 버튼** = 전송. 일기는 여러 줄이 기본이므로 Enter를 전송에 쓰지 않는다. 무입력 자동 전송 없음.
5. **터치 필기**: 스타일러스(`pointerType === 'pen'`) 우선. 손가락 입력은 설정에서 허용/차단 토글(팜 리젝션 대용). 캔버스 영역은 `touch-action: none`으로 스크롤 충돌 차단.
6. **되돌릴 수 없음의 고지**: 첫 진입 시 한 줄로만 알린다 — `여기 적은 것은 저장되지 않고, 곧 사라집니다.` 확인 버튼 없음. 그 문장 자체도 사라진다.
7. **새로고침 = 완전한 소멸.** 복구 UI 없음. `beforeunload` 경고도 띄우지 않는다(그게 이 제품의 약속이므로).

## 6. AI 설계

### 6.1 모델
- `gpt-5.4-mini` (snapshot `gpt-5.4-mini-2026-03-17`), **Responses API + streaming**.
- 컨텍스트 400K / 출력 128K, 텍스트+**이미지 입력**, `reasoning.effort` 지원(`none`~`xhigh`).
- 설정: `reasoning: { effort: 'low' }` — 공감적 짧은 응답에 과한 추론은 지연만 늘린다. 응답 길이 상한을 프롬프트와 `max_output_tokens`로 이중 제한.
- 단가(1M 기준) 입력 $0.75 / 캐시 입력 $0.075 / 출력 $4.5 → 프롬프트 캐싱을 위해 시스템 프롬프트를 고정·선두 배치.

### 6.2 페르소나 — "The Page"

경청이 8할, 인격이 2할. 톰 리들의 일기장이 그랬듯 **분명히 누군가가 거기 있다**는 감각은 주되, 조종하거나 유도하지 않는다.

원칙(시스템 프롬프트로 인코딩):
- **짧게 쓴다.** 기본 1–3문장. 손으로 쓰는 존재라 길게 못 쓴다는 설정이 곧 UX 제약.
- **먼저 되받아 적는다.** 사용자가 쓴 말 중 한 조각을 그대로 옮겨 적고 시작할 수 있다("`오늘도 버텼다`, 라고 썼네요.").
- **판단·조언·해결 금지.** 요청받기 전에는 제안하지 않는다.
- **하루 회고를 돕는 질문**은 하되 한 번에 하나만.
- **자기 인격의 흔적**: 종이·잉크·시간에 대한 1인칭 감각을 가끔 드러낸다("여기 적힌 건 곧 옅어질 거예요. 그래도 지금은 읽고 있어요."). 신비주의는 절제.
- **거짓 기억을 만들지 않는다.** 세션 밖의 일을 아는 척하지 않는다.
- **마크 사용**: 사용자의 말에서 스스로 중요하다고 느낀 한 조각에만 마크를 건다. 응답당 최대 1개.
- **언어**: 사용자의 UI 언어 및 입력 언어를 따른다.

### 6.3 InkScript — 마크 전달 방식

별도 tool call 없이 스트리밍 텍스트 안에 인라인 마크업을 흘려보낸다(스트리밍 중 즉시 파싱 가능).

```
__밑줄__        → underline
((동그라미))     → circle
==형광펜==       → highlight
```

파서는 스트리밍 청크 경계를 견디는 증분 파서로 구현(부분 토큰 버퍼링). 미지의 마크업은 그대로 평문 출력(안전 실패).

### 6.4 API 계약

`POST /api/converse`
```jsonc
{
  "mode": "text" | "ink",
  "text": "...",                  // mode=text
  "image": "data:image/png;base64,...",  // mode=ink
  "history": [{ "role": "user"|"assistant", "content": "..." }],  // 클라 보관분
  "locale": "ko" | "en"
}
```
응답: `text/event-stream`
```
event: transcript   data: {"text":"..."}       // ink 모드에서만, 화면 비표시·히스토리용
event: delta        data: {"text":"..."}
event: done         data: {"usage":{...}}
event: error        data: {"code":"rate_limited"|"upstream"|"invalid"}
```

- Route Handler: `export const runtime = 'nodejs'`, `export const dynamic = 'force-dynamic'`, `export const maxDuration = 60`.
- 히스토리는 **클라이언트가 보관**하고 매 요청에 동봉한다 → 서버 무상태. 서버는 아무것도 저장하지 않는다(이것이 제품 약속의 기술적 근거).
- 히스토리 상한 24턴 / 12,000자. 초과분은 가장 오래된 것부터 절삭.

### 6.5 안전

- **입력 검증**: zod. 텍스트 4,000자, 이미지 1.5MB, 히스토리 크기 상한.
- **레이트 리밋**: 인스턴스 메모리 기반 토큰 버킷(IP당 분당 12회, 시간당 120회) — best-effort임을 문서화하고 프로덕션 업그레이드 경로(Upstash Ratelimit)를 README에 명시.
- **위기 대응**: 자·타해 위험 신호 감지 시 프롬프트 지침에 따라 판단하지 말고 곁에 머무는 문장 + 지역 자원 안내. UI에도 상시 접근 가능한 도움 패널.
  - 🇰🇷 자살예방상담전화 **109**, 정신건강위기상담전화 **1577-0199**
  - 🌐 US/CA **988**, UK **116 123**, 그 외 `findahelpline.com`
- **고지**: `/about` 및 최초 진입 시 1회 — 의료·상담 서비스가 아님, 응급 시 즉시 지역 응급번호.
- **키 보안**: `OPENAI_API_KEY`는 서버 전용. 클라이언트 번들 노출 검증 테스트 추가.
- **프라이버시**: 서버 영속 저장 0. 로그에 사용자 콘텐츠 미기록. Vercel 함수 로그에도 본문이 남지 않도록 에러 로깅 시 콘텐츠 마스킹.

### 6.6 목(mock) 모드

`OPENAI_API_KEY`가 없거나 `MOCK_AI=1`이면 라우트가 **정해진 응답을 실제 스트리밍 속도로 흘려보낸다.** 이유:
- 키 없이도 잉크 엔진 개발·데모·E2E 테스트가 가능하다.
- 공개 데모 배포에서 비용 없이 인터랙션을 보여줄 수 있다.
- 키 누락이 500 에러가 아니라 명확한 개발자 경고로 나타난다.

## 8. 접근성 — 사라지는 UI의 책임

사라지는 텍스트는 접근성 위험이 크다. 다음을 **v1 필수**로 둔다.

1. `prefers-reduced-motion: reduce` → 필기 애니메이션은 즉시 표시, 페이드는 유지하되 blur 제거·시간 2배.
2. **스크린리더용 라이브 리전**: 시각적 소멸과 무관하게 `aria-live="polite"`에 전문(全文)이 들어간다. 스크린리더 사용자는 텍스트를 잃지 않는다.
3. **붙잡기(hold)**: 마우스 롱프레스 / `Space` 홀드 / 설정의 "자동 소멸 끄기". 읽기 속도가 느린 사용자를 배제하지 않는다.
4. 모든 컨트롤 키보드 접근 + 가시적 포커스 링 + `aria-pressed` 상태.
5. 소멸 속도 설정: `짧게 30s / 기본 90s / 길게 5분 / 끄기`.
6. 색만으로 두 목소리를 구분하지 않는다 — 서체와 들여쓰기로도 구분.

### 14.2 단계

**1단계 · 정체성** — `src/app/icon.svg`, `apple-icon.png`, `opengraph-image`,
헤더 마크, `themeColor` 오타(`#0e1013` → `#0f1216`) 수정.

**2단계 · 속도와 건네기** — `WRITE_CPM` 120/190/280 → **135/215/310**.
`InkCanvas`: 건네기 버튼을 항상 보이게(비활성 시 흐리게), 획이 멈추면
4초 카운트다운 링이 차오르고 다 차면 건네진다. 새 획·지우기는 링을 되돌리고,
"아직요"를 누르면 그 장(章) 동안은 수동으로 바뀐다. 설정에서 끌 수 있다.
`Composer`도 같은 버튼 규칙을 따른다.

**3단계 · 빈 페이지 모드** — `pageMode: "blank" | "keep"`, 기본값 **`blank`**.
- `blank`: 건넨 글은 곧바로(≈900ms 머문 뒤 1.4초에 걸쳐) 종이에 스며들고,
  답장은 다 쓰인 뒤 **읽는 데 걸릴 만큼**(글자 수 ÷ 420 cpm, 최소 4.5초,
  최대 25초) 머물다 사라진다. 결과적으로 항상 빈 페이지에서 쓴다.
- `keep`: 지금까지의 동작(모두 함께 머물다 `사라지는 속도` 설정만큼 뒤에 사라짐).
- 첫 인사말은 **고정(pinned)** 되어 첫 글을 건넬 때까지 사라지지 않는다.
  빈 화면이 첫인상이 되면 안 된다.
- `사라지는 속도` 설정은 빈 페이지 모드에서 **읽는 시간의 배율**이 된다
  (짧게 ×0.6 · 기본 ×1 · 길게 ×1.8). 컨트롤 하나가 두 모드에서 모두 뜻을 갖는다.
- `사라지는 속도: 사라지지 않게`가 이긴다. 이때 빈 페이지 모드는 무력화되고
  설정에 그 사실을 적는다.

**4단계 · 손글씨체** — 라틴+한글 짝 네 가지.

| 이름 | 라틴 | 한글 |
|---|---|---|
| 볼펜 `pen` | Caveat | Gaegu |
| 펜촉 `quill` | Shadows Into Light | Nanum Pen Script |
| 붓펜 `brush` | Kalam | Nanum Brush Script |
| 또박또박 `print` | Patrick Hand | Hi Melody |

기본값은 내 손 `pen` / 페이지의 손 `quill`(지금과 동일). 첫 페인트에 보이는
선택이므로 테마·모드와 같이 **쿠키**로 저장하고 `<html>`의 `data-hand-*`로 적용한다.

**5단계 · 첫 사용자** — 첫 방문에만 뜨는 비모달 안내 카드(세 줄: 여기 적는 것 ·
사라진다는 것 · 눌러서 붙잡는 법), 설정에 "안내 다시 보기". 답장을 기다리는 동안
펜촉이 조용히 깜빡이는 **생각 중** 표시(`aria-live`). `notice` 문구 정리.

**6단계 · README와 영어 GIF** — 영어 로케일로 `writing.gif`, `fading.gif`,

## 15. v1.2 계획 — 한 번에 한 손

### 15.1 무엇이 문제인가

입력 영역이 잉크 **아래**에 일반 흐름으로 놓여 있다. 그래서

1. 답장이 한 줄씩 자라는 동안 커서가 계속 아래로 밀리고,
2. 답장이 사라지는 순간 커서가 훅 위로 올라온다.

턴마다 커서가 왔다갔다 하는 셈인데, 정작 그 시간 동안 사용자는 아무것도 쓸 수
없다(페이지가 쓰는 중에는 입력이 잠겨 있다). **움직일 이유가 없는 것이 움직인다.**

영화의 리듬은 그게 아니다. 해리가 쓰면 종이가 삼키고, 리들의 글씨가 나타났다
사라지고, 그제서야 다시 해리가 쓴다. **종이는 한 번에 한 손의 것이다.**

### 15.2 어떻게 고치는가

**차례(turn ownership).** 빈 페이지 모드에서 입력 영역은 *내 차례일 때만* 존재한다.

```
내 차례 = 페이지가 쓰는 중이 아니고 && 종이에 (고정된 인사말 말고) 잉크가 없다
```

- 건네는 순간 입력 영역이 사라진다. 그 아래에는 아무것도 없으므로 화면은 흔들리지
  않는다.
- 답장이 다 사라져 종이가 비면, 입력 영역이 **빈 종이의 맨 위**에 다시 나타난다.
- 결과적으로 두 번째 턴부터 커서 위치는 **매번 같다**. 첫 턴만 인사말 한 줄 아래에서
  시작한다.
- 돌아올 때는 툭 튀어나오지 않게 640ms 동안 떠오른다. 타이핑 모드이고 이미 한 번
  건넨 적이 있으면 커서까지 되돌려준다.
- `쌓아두기` 모드에는 적용하지 않는다. 거기서는 대화가 쌓이는 것이 설계이고,
  입력 영역이 그 아래를 따라가는 것이 맞다.
- `#entry` 래퍼는 항상 남긴다. 건너뛰기 링크의 목적지가 사라지면 안 된다.

**스며드는 속도.** 건넨 글이 사라지는 데 900ms + 1.8초가 걸린다. 영화의 "샥"에 비하면
느긋하다. **600ms + 1.2초**로 줄여 차례가 넘어가는 리듬을 조인다.

### 15.3 검토할 것

- 교착 없음 — 답장이 `onWritten`에 도달하지 못하면 입력이 영영 돌아오지 않는다.
  이는 기존 `busy` 잠금과 동일한 위험이며 새로 생기는 것은 아니다. `사라지지 않게`는
  애초에 빈 페이지 모드를 끄므로 여기 해당하지 않는다.
- 붙잡고 있는 동안(hold-to-keep) 페이드가 멈추면 입력도 계속 숨겨진다. 손을 떼면
  이어진다 — 의도된 동작.
- `페이지 비우기`는 `turns`를 비우므로 입력이 즉시 돌아온다.
- axe 재실행, 빈 페이지 타임라인 재측정, `쌓아두기` 회귀 확인.

### 15.4 단계

1. 차례 소유권 + 복귀 애니메이션 + 커서 복원.
2. 스며드는 속도 조정.
3. 설정 문구에 차례 개념 반영.
4. 검증(axe · 타임라인 · 회귀) 후 `blank.gif` 재촬영, README 갱신.

### 15.5 진행하면서 추가된 것

작업 중 나온 요청 셋과, 구현하다 드러난 버그 둘.

| 항목 | 내용 |
|---|---|
| 쓰는 속도 | 135/215/310 → **175/280/400 cpm**. 실제 손보다 빠르지만 의도적이다. 어느 선을 넘어 느려지면 "쓰는 중"이 아니라 "기다리는 중"으로 읽힌다. |
| 스며드는 속도 | 900ms + 1.8초 → **600ms + 1.2초**. 손이 바뀌는 박자를 조인다. |
| 커서 제거 | 리빌 가장자리를 따라가던 펜촉(nib)을 **삭제**. 본문 크기에서는 그것이 줄을 따라 깜빡이는 텍스트 커서로 읽혔다. 종이에 나타나는 손글씨 앞에는 아무것도 없다. |
| 이름 | 답하는 쪽을 **리들(Riddle)**로 부른다. "AI가 쓰는 속도"는 상대를 시스템 설정으로 프레이밍했다. 프롬프트에도 이름을 넣어 물어보면 답할 수 있게 했되, 프로그램이냐고 직접 물으면 한 문장으로 인정하고 다시 상대에게 돌아간다. |
| **버그 · restAll** | 인사말은 천천히 쓰이므로 **다 쓰이기 전에 글을 건넬 수 있다.** 그러면 뒤늦게 끝난 인사말이 `restAll()`을 불러, 아직 쓰이는 중인 답장을 쉬게 하고 상태를 idle로 되돌려 문장 도중에 페이지를 열어버렸다. → `restFrom(id)`: 그 턴과 그 이전만 쉬게 하고, 뒤에 답장이 떠 있으면 idle로 가지 않는다. |
| **버그 · 빈 답장** | 스트림이 글자를 하나도 내놓지 않으면, 페이드시킬 것이 없어 완료 신호도 오지 않는 노드가 종이에 영원히 남았다. 빈 페이지 모드에서는 그대로 교착. → `finishReply`가 빈 노드를 버리고 종이를 돌려준다. |

## 16. v1.3 — 두 배 빠른 손, 그리고 그리는 리들

### 16.1 요청

1. **리들이 쓰는 속도를 2배 이상.**
2. **글만 말고 간단한 그림/아이콘도 그리게.** (v1.2에서 로드맵으로 미뤄둔 항목)

### 16.2 속도 — 왜 `cpm`만 올리면 2배가 안 되나

`WRITE_CPM`은 글자당 시간만 정한다. 쉼(`pauseAfter`)은 절대값이다 — 줄바꿈
420ms, 마침표 320ms, 쉼표 140ms, 공백 60ms. 두 문장짜리 답장에서 쉼이 전체의
약 11%를 차지하므로, `cpm`만 2배로 올리면 실제 체감은 1.8배에 그친다.

그래서 둘 다 손본다.

| | 지금 | v1.3 |
|---|---|---|
| `WRITE_CPM` | 175 / 280 / 400 | **360 / 600 / 860** |
| 쉼 | 고정 ms | **손 속도에 비례** — `pauseAfterMs × (baseMs / 기준)` |

기준은 새 `normal`(600 cpm)이다. 따라서 `normal`에서는 지금 적어둔 쉼 값이
그대로 유효하고, `slow`는 더 오래 쉬고 `brisk`는 덜 쉰다. 느린 손이 더 오래
머무는 것이 자연스럽다.

두 문장 답장 기준 약 14.5초 → **약 6.7초** (2.16배).

**바꾸지 않는 것** — `readDwellMs`(읽는 속도는 읽는 사람의 것이다),
`ABSORB_*`, 페이드 길이.

**규칙 4와의 긴장.** "절대 빠르게 만들지 말 것"은 건너뛰기 어피던스와 즉시
표시를 막는 규칙이다. 600 cpm에서도 한 글자는 100ms(60fps에서 6프레임)이고
답장 하나는 7초에 가깝다. 여전히 "쓰이는 중"으로 읽힌다.

### 16.3 그리는 리들

로드맵에 적어둔 그대로: **리들이 스펙을 내보내고, 마크를 그리는 그
`stroke-dashoffset` 엔진이 획 순서대로 그린다.** 세 번째 타이밍 메커니즘은
없다.

**문법** — `[[이름]]`. 어휘는 아홉 개로 고정한다.

```
star  heart  sun  moon  cloud  leaf  wave  spiral  arrow
```

임의의 SVG를 모델에게 맡기지 않는 이유는 둘이다. 신뢰성 — 모델이 그린 패스는
못생기거나 깨진다. 그리고 안전 — 마크업이 렌더러에 도달하지 않는다.

**파서** (`inkscript.ts`)

- `ParsedInk`에 `source`와 `glyphs`가 붙는다.
- `text`에는 그림 자리마다 U+FFFC(OBJECT REPLACEMENT CHARACTER)가 들어간다.
  자리를 차지해야 마크 범위와 자소 인덱스가 어긋나지 않는다.
- 스트리밍 중 닫히지 않은 `[[`는 **거기서 잘라낸다.** 이름을 글자로 흘려보낸 뒤
  지우면 접두사 안정성이 깨진다. 스트림이 끝난 뒤라면 그냥 글자다.
- 모르는 이름 → 글자.
- 답장당 **최대 두 개**. 그 뒤는 조용히 버린다. 어느 접두사에서든 같은 판정이
  나오므로 안정성은 유지된다.

**기하** (`lib/ink/glyph.ts`) — 이름마다 24×24 상자 안의 패스 목록을 순서대로
돌려준다. 마크와 같은 시드 노이즈로 흔들고 같은 `smoothPath`로 부드럽게 만든다.
`pathLength="1"`이므로 그리기는 `stroke-dashoffset: 1 → 0`.

**타이밍** (`segment.ts`) — 그림은 자소 하나다. 고정 길이(기준 템포에서
1300ms, 속도 설정에 비례)를 갖고, 그린 뒤 펜을 드는 쉼이 붙는다. 스크립트
정규화에서는 **제외한다** — 정규화는 한국어와 영어의 템포를 맞추기 위한
것이고, 그림은 어느 쪽도 아니다.

**렌더** (`InkGlyph.tsx`) — 그 글자 자리에 인라인 `<svg>`. 획마다 제 몫의
지연을 받아 순서대로 나타난다.

**접근성** — `history`에는 토큰이 그대로 남고(리들도 자기가 뭘 그렸는지 알아야
한다), `Transcript`가 읽을 때 지역화된 라벨로 바꾼다. U+FFFC는 렌더러 밖으로
나가지 않는다.

### 16.4 단계

1. 속도 — `WRITE_CPM`, 비례하는 쉼, 테스트.
2. 파서 — `[[이름]]`, `source`, `glyphs`, 접두사 안정성 테스트.
3. 기하 — `glyph.ts`, 테스트.
4. 타이밍 + 렌더 — 자소 자리, `InkGlyph`, CSS, 동작 감소.
5. 배선 — 프롬프트, 목업, `readDwellMs`, 라벨, i18n.
6. 검증 — `/lab`과 Playwright로 손 확인, axe 재실행.
7. 문서 — README, CLAUDE.md, 이 문서.

### 16.5 검토할 지점

- `[[star]]`를 어느 위치에서 자르든 텍스트가 접두사로 자라기만 하는가.
  → 모든 접두사에 대한 속성 테스트.
- 그림이 마크 범위 안에 있어도 측정되는가. → 자리 요소에 `data-i`가 있는가.
- 두 개 상한이 나중 텍스트에 따라 달라지는가. → 아니다.
- 600 cpm이 아직 "쓰는 중"인가. → 손으로 확인.
